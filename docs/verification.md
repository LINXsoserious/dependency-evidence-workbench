## 可复现测试

命令：`python -m unittest discover -s tests -v`。

本地结果：30 项测试通过。覆盖清单解析、重复版本与位置、条件标记、未锁定项、npm 开发依赖、逐项分页、响应位置错配、网络失败、公告详情失败、撤回状态、缺失风险级别、别名合并、按包提取修复边界、导出错误信息、CSV 公式前缀、CLI 退出码与文件保留、Streamlit 流程。

关键行为先编写失败断言，再实现或修正；包括异常版本、遗漏错误信息的导出、未解析字段的 CSV 公式防护。AppTest 在普通测试进程中产生 missing ScriptRunContext 提示，但应用无异常。

测试仅用固定快照和可控响应。GitHub Actions 的 Ubuntu / Windows 实际结果见仓库 Actions 页面，不能用工作流配置本身证明通过。

## 实际 API 验证

1. OSV POST /v1/querybatch：对 npm minimist 1.2.5 和 PyPI requests 2.19.1 进行真实查询，得到公告编号；按编号读取真实详情。
2. 脚本获取 5 个示例依赖版本和 18 条原始公告对象，写入带获取时间与许可来源的演示快照。
3. [npm 联网报告](evidence/npm-live-report.json)：检查 3 个唯一依赖版本，2 个命中，合并为 6 组漏洞；无查询 / 详情错误，CLI 退出码 1。
4. [专用环境联网报告](evidence/installed-environment-report.json)：对实际安装的 35 个包检查，查询完整，当时未命中有效记录，CLI 退出码 0。这不推导环境安全，也不表示未来不会出现公告。
5. 混合示例存在 2 条无法确定精确版本的声明，退出码 2；未被快照覆盖的版本同样返回不完整状态。
